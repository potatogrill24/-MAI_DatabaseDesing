# Лабораторная работа 2

## Формулировка задания

Создать базу данных с таблицей `account`: `account_id int` — первичный ключ, `val int` — остаток. Добавить счета `(1, 100)` и `(2, 100)`, вывести содержимое таблицы.

Создать хранимую процедуру по слайду 76. Модифицировать базу и процедуру так, чтобы банковские операции записывались в отдельную таблицу: счет отправителя, счет получателя, сумма и время операции.

На приложенном слайде фактически показана **функция** `bank.trans(p_id_from int, p_id_to int, p_val int) RETURNS int`. Поэтому реализована именно функция, вызываемая через `SELECT`, с кодами возврата `0` при успехе и `-1` при отказе.

## Файлы и запуск

Используется отдельная база `lab02_bank`, таблицы и функция расположены в схеме `bank`. Команды выполняются из `MAI_DatabaseDesing`:

```bash
# База и два счета по 100.
sudo -u postgres psql -X -d postgres -f lab_02/00_create_database.sql

# Исходная функция по слайду.
sudo -u postgres psql -X -d lab02_bank -f lab_02/01_transfer_original.sql

# Замена функции на версию с журналом и дополнительными проверками.
sudo -u postgres psql -X -d lab02_bank -f lab_02/02_transfer_logged.sql

# Проверка переводов, остатков и журнала.
sudo -u postgres psql -X -d lab02_bank -f lab_02/03_check.sql
```

Для создания базы нужны права `CREATEDB`. Все скрипты включают `ON_ERROR_STOP`: ошибка прекращает выполнение. Для проверки кода завершения сразу после запуска выполните `echo $?`; ожидается `0`.

Повторный запуск создания базы не удаляет ее и не сбрасывает остатки. Файл `01_transfer_original.sql` заменяет текущую функцию исходной, без журналирования; после него обязательно выполните `02_transfer_logged.sql`, чтобы установить окончательное решение.

## Решение

- `bank.account` сохраняет структуру задания. Дополнительно запрещены NULL и отрицательные остатки.
- `01_transfer_original.sql` воспроизводит алгоритм слайда: чтение остатка, проверка `m - p_val > 0`, списание, зачисление, возврат результата. Указаны схема таблицы и язык PL/pgSQL.
- `02_transfer_logged.sql` добавляет `bank.operation_log`: идентификатор, `account_from`, `account_to`, `amount`, `operation_time`. Время типа `timestamptz` формируется через `clock_timestamp()` в момент добавления записи.
- Модифицированная функция отвергает неположительную сумму, NULL, одинаковые и отсутствующие счета. Оба счета блокируются через `FOR UPDATE` в порядке идентификаторов, чтобы конкурирующие переводы не использовали один остаток одновременно.
- Условие слайда сохранено буквально: после списания остаток должен быть **строго больше нуля**. Перевод всей имеющейся суммы возвращает `-1`.
- Списание, зачисление и запись журнала участвуют в одной транзакции. При откате отменяются все три изменения. Внутри функции нет `COMMIT`.

Журнал содержит успешные переводы через `bank.trans`. Отказы не журналируются; прямой ручной `UPDATE bank.account` эту функцию не вызывает. Ошибки СУБД, например переполнение `int`, прерывают операцию с ошибкой, а не преобразуются в код `-1`.

## Проверка и самостоятельный вызов

Для `03_check.sql` нужны исходные остатки 100 и 100; счет 999 должен отсутствовать, чтобы проверить перевод на несуществующий счет и с него. Успешный перевод 30 возвращает **0**, остатки становятся **70 и 130**, в журнале появляется одна запись `1 → 2` на сумму **30** с временем операции. Затем проверяются отказы: недостаток средств, попытка обнулить счет, отсутствующие счета, некорректные параметры. Отказы не должны менять остатки и журнал.

При успехе выводится сообщение **«Все проверки пройдены»**. Финальный `ROLLBACK` возвращает остатки 100 и 100 и отменяет учебную запись журнала. Номер операции может быть пропущен: последовательность `IDENTITY` не откатывается.

Для самостоятельного перевода подключитесь к `lab02_bank` и выполните:

```sql
BEGIN;

SELECT bank.trans(1, 2, 30);

SELECT * FROM bank.account ORDER BY account_id;
SELECT * FROM bank.operation_log ORDER BY operation_id;

COMMIT;
```

Этот пример сохраняет перевод. Для пробного вызова замените `COMMIT` на `ROLLBACK`. После сохранения перевода остатки уже не будут исходными, поэтому `03_check.sql` завершится сообщением о неподходящих начальных данных.

Все скрипты проверены на отдельной базе в PostgreSQL 18. Дополнительно проверены откат списания и зачисления при ошибке записи журнала и два параллельных перевода по 80 с одного счета с остатком 100: прошел только один перевод, итоговые остатки — 20 и 180, в журнале одна операция. Рабочие базы при проверке не изменялись.
